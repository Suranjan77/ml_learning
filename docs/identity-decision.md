# Identity Decision

Status: adopted
Updated: 2026-07-13

## Decision

Keep the descriptive name **Machine Learning Visualisations**.

The project does not need a coined product name. Its identity comes from the
work itself: direct model controls, retained comparisons, paper-and-ink visual
styling, compact technical labels, and explicit notes about computation and
simplification.

## Public language

Use short, literal descriptions of what is on the page and what a control does.

- Name the model, input, result, or limitation directly.
- Prefer concrete verbs such as `change`, `move`, `compare`, `fit`, and `route`.
- Avoid manifesto headlines, virtue labels, and claims about how visitors
  should feel.
- State privacy as implementation fact: no accounts, analytics, advertising,
  or tracking cookies.
- Let the interaction demonstrate quality instead of describing the project as
  distinctive, trustworthy, memorable, or exceptional.

## Visual identity

Retain the existing warm neutral surfaces, dark ink, muted green, rust accent,
serif display type, sans-serif body type, and monospaced technical notation.
Recognition should come from stable semantic treatments:

- solid marks show the current state;
- muted or dashed marks show a kept state or forecast;
- annotations attach to the changed feature where space allows;
- failure uses text or shape in addition to colour;
- controls remain adjacent to the result they change.

These rules are guidance, not a universal exhibit layout. Each scene keeps the
choreography required by its own model.

## Revisit only when

Reconsider naming only if the descriptive title creates a concrete navigation,
attribution, search, or publishing problem. Do not reopen naming solely to make
the project sound more like a product.
